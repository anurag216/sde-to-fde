# Product principles

## 1. Career outcome before business outcome

The primary product is the learner's engineering transformation. Commercialization is a secondary experiment.

When those goals conflict, choose the path that creates stronger engineering capability rather than prettier SaaS infrastructure.

## 2. Never erase prior experience

An experienced SDET may already understand production concerns through automation, CI/CD, browser infrastructure, queues, cloud deployments, observability, or enterprise workflows.

The system should diagnose implicit competence and attach formal CS/SWE vocabulary to it rather than forcing a beginner path.

## 3. Productive struggle is a feature

Default learning loop:

1. Problem
2. Attempt
3. Failure/feedback
4. Progressive hint
5. Discovery
6. Formal explanation
7. Different-context repetition
8. Mastery evidence

## 4. AI is a tutor, not an answer dispenser

Assistance levels:

1. Conceptual hint
2. Directional hint
3. Specific hint
4. Pseudocode
5. Partial solution
6. Full solution

The user should make a genuine attempt before higher assistance levels unlock unless accessibility/safety requires otherwise.

## 5. Mastery requires evidence

Passing one challenge is not mastery. Evidence should eventually combine:

- implementation
- debugging
- explanation
- design reasoning
- transfer to a different scenario
- delayed retention

## 6. DSA is integrated, not worshipped

DSA exists to build CS vocabulary, implementation confidence, performance intuition, and interview readiness. The target is not competitive programming.

## 7. FDE is a destination track, not an excuse to avoid coding

FDE progression should increase both ambiguous/customer-facing problem solving and production implementation depth.

## 8. Never invent competence metrics

Do not assign precise skill scores from biography alone. Skill levels must be backed by diagnostic or usage evidence.
